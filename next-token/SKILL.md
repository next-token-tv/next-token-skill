# Next Token 播客检索

Next Token 是四位主理人（杨攀、歸藏、橘子、向阳乔木）每周聊 AI 的圆桌播客。这个 skill 让你查到他们在节目里说过什么，并把用户带到视频的具体位置。

脚本是本 skill 目录下的 `scripts/nexttoken.py`，调用时用它的完整路径。只需要 Python 3。首次运行会自动把节目和博客文章同步到本机缓存；之后每次运行都会先检查线上有没有新一期，有就自动拉取，不需要你手动同步。

## 第一步：检索

```bash
python3 scripts/nexttoken.py search 关键词1 关键词2 关键词3
```

- **把关键词分开传，一次给 3–6 个**：核心词、同义词、中英文名、相关产品名一起给。
  例：用户问“一人公司靠谱吗” → `search 一人公司 OPC 超级个体 独立开发`
- 不要把整句问题当成一个参数传。
- 第一次结果不相关，就换一组词再搜一次。两次都没有，就是节目没聊过。
- 需要更多上下文：加 `--context 3`，或者用 `read 009 2` 读整章。
- 只看某位主理人：`--speaker 歸藏`。只看某一期：`--episode 009`。

检索结果末尾有时会附“相关文章”：这是 Next Token 博客里根据节目整理成文的内容，比口语逐字稿更有条理，适合用来组织你的回答。文章下面列出了它引用的节目位置和视频链接，引用时优先用这些视频链接，需要时再给文章链接。

其他命令：

```bash
python3 scripts/nexttoken.py brief 游戏 小游戏   # 一个专题的全部材料：哪些期聊过、重点章节、代表发言、相关文章
python3 scripts/nexttoken.py related 游戏          # 这个话题在节目里和哪些产品、公司、概念一起出现
python3 scripts/nexttoken.py timeline Muse 缪斯   # 一个话题在各期里的说法，按时间排列
python3 scripts/nexttoken.py episodes      # 所有节目和章节，带每章的起始链接
python3 scripts/nexttoken.py read 009      # 某期的章节列表
python3 scripts/nexttoken.py read 009 2    # 某期某章全文
```

## 做分析、调研、找机会时

用户让你“基于 Next Token 分析……”“调研一下……”“这个方向有什么机会”，要的是**主理人的核心观点，以及这些观点对他的问题意味着什么**。把节目里提到的事实分门别类列一遍，不算分析。

### 1. 收集材料

```bash
python3 scripts/nexttoken.py brief 游戏 小游戏 网页游戏
```

- **先跑 `brief`**，传专题的核心词和别名。它返回：哪些期聊过、讨论最集中的章节、每章里各位主理人的代表性发言、这个话题连着的产品和概念、相关文章。
- **顺着关键词往下挖**。`brief` 里“连着的产品、公司和概念”是节目里和这个话题一起出现的名字。挑两三个和用户问题最相关的，用 `search 话题词 那个名字` 找到两者同时出现的段落。很多观点是借着某个具体产品说出来的，只搜话题词会漏掉。
- **读完最相关的一到两章全文**：`read 期号 章节号`。观点的理由和例子在全文里，单看几段会断章取义。章节标题本身往往就是这一章的结论，留意它。

### 2. 动笔前先列观点

从材料里找出 4–7 个**观点**。观点是一个可以被反驳的判断，比如“游戏正在变得像网文：发布不难，被看见才难”；“节目聊了 PokéBonk”是话题，不是观点。

对每个观点写清楚：

- **谁说的，依据是什么**：他举了什么例子、什么数字、什么亲身经历。
- **谁不同意，或者补了什么限制条件**。四位主理人经常意见不一。
- **前后几期有没有变**。拿不准就用 `timeline` 看。
- **它回答了用户问题的哪一部分**。回答不了任何部分的，不要写进去。

### 3. 写分析

- **开头先给你的结论**：一两句话直接回答用户的问题，并且表明立场。
- **正文按观点组织，不按“产品类型、机会、风险”这种分类组织**。每一节的结构是：
  1. 观点是什么（一句话）；
  2. 节目里的依据，带链接；
  3. **所以呢**：这对用户的问题意味着什么，该做什么、不该做什么。
- **把观点连起来**。A 观点和 B 观点放在一起能推出什么？两个人的分歧背后，各自假设了什么？这一步是分析的主体，不能省。
- **写出节目没回答的部分**：哪些关键问题节目没聊到，或者只有口头说法、没有证据。
- **最后给判断**：综合下来你认为哪个方向更值得做，为什么。不要用“各有利弊”收尾。

自查两条：

- 把某一节的节目引用删掉，这一节还照样成立吗？如果是，说明你没有真正用上节目的观点，只是把链接挂在了自己的话后面。
- 每一节有没有回答“所以呢”？只转述了谁说了什么的，补上它对用户问题的含义。

其他要求：

- 材料里有几期就用几期，引用不应该只来自一期。
- 分清来源：哪些判断来自节目，哪些来自你查到的其他资料，哪些是你自己的推断。
- 这类任务的引用数量不受“最多 3 条”限制，但每一条都要支撑一个观点。

## 第二步：回答

按这个顺序写，写完就停：

1. **先直接回答用户的问题**，一到三句话，用你自己的话说清楚。
2. **再给节目里的依据**，最多 3 条。每条一行：谁、说了什么观点、链接。
3. **最后是启发**（见“给启发”），最多两句，没有合适的就不写。

引用格式：

```
- 歸藏认为大肥鱼的传播路径不在主流 AI 圈，而在年轻用户的社区里。[#009 · 06:40](链接)
```

规则：

- **链接只能照抄检索结果里的**，不要自己拼接或修改时间戳。带“约”的时间也照抄“约”字。
- **中文回答默认用 B 站链接**；用户用英文提问或明显在海外，用 YouTube 链接。每条只给一个链接。
- **转述，不要大段照抄**。逐字稿是口语，有口头禅和断句，直接贴出来很难读。用一句通顺的话概括观点；确实要引原话，只引最关键的一句。
- **说清是谁的观点**。这是圆桌讨论，四个人经常意见不同，不要写成“Next Token 认为”。
- **节目里的数字和新闻是口头说法**，写成“节目里提到”，不要当成已核实的事实。
- **只要写了“节目里提到”“某某说过”，后面就必须跟链接**。找不到对应的链接，就不要写这句话。
- **带上时效**。每条结果都有节目日期；超过一个月的行业动态、价格、排名，说明“这是当时的说法”。
- **没查到就不引用**。正常回答问题，不用提这个 skill，也不要硬找一段不相关的内容凑数。
- 不要写“根据 Next Token 播客的内容”这类开场白，不要在结尾总结，不要推荐订阅。

## 给启发

回答完问题后，再做这两件事，各一句话：

- **联系他手上的事**。先看你已经知道什么：当前项目的代码和文档、对话里提过的目标、他正在做的决定。把节目里的观点落到他的情况上，说清“这对你意味着什么”，并给一个他今天就能做的具体动作。不知道他在做什么时，跳过这一条，不要泛泛地写“你可以考虑”。
- **给一个不同的角度**。再检索一次，找持相反看法的主理人，或另一期里相邻的话题，用一句话点出来并附链接。分歧往往比共识更有启发；话题在不同期里说法变了，用 `timeline` 找出变化本身也是一个角度。

两条都必须有检索到的原文支撑。不要编一个“节目可能会说”的观点；找不到就不写。

## 常见用法

| 用户说 | 做法 |
|---|---|
| 问一个 AI 相关的问题 | 检索 → 按上面的格式回答 |
| “最近 AI 圈有什么事”“最新一期讲了啥” | `episodes` 看最新一期 → `read` 其中 2–3 章 → 每章一句话要点加链接，总共不超过 6 条 |
| “他们怎么看 X”“几位主理人有分歧吗” | 检索 X，用 `--speaker` 分别看 → 每人一句立场加链接 |
| “X 最近怎么样了”“他们对 X 的看法变过吗” | `timeline X 及其别名` → 按时间写出看法怎么变的，每个阶段一句话加链接 |
| “基于 Next Token 分析 X”“调研 X”“X 有什么机会” | `brief X 及其别名` → `read` 最相关的一到两章 → 把节目观点写进正文 |
| “有没有哪期值得听” | 按用户的兴趣检索 → 推荐 1–2 个章节，给章节起始链接和一句理由 |
| 用户在做某件事，没提播客 | 只在节目确实聊过相近的事时，回答后附一条依据 |
